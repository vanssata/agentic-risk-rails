# ADR-0011: Състоянието е journal на задача, знанието е в обикновените документи, всичко друго е проекция или кеш

Статус: прието (2026-10-31). Източник: `docs/design/research-fable.md` §12.

## Контекст

днес `state.py` (5.4k реда) пази мутируем `state.json` с fallbacks и migrations, compact memory (3.8k реда) е отделна подсистема, а `.ai/project/` е генериран survey, който остарява.

## Решение

§16 — един append-only, hash-chained JSONL файл на задача (`.rr/run/` за текущата, `.rr/tasks/` за затворените, committed през PR-а на задачата); `status`, `cost`, `risks`, `recall` са проекции; знанието за проекта живее в `AGENTS.md`, `docs/`, `docs/adr/`, `specs/` по OpenSpec и `docs/known-risks.md`; изводимото (repo map, символи) се извлича при нужда и се кешира извън repo-то по SHA; `rr rebuild` възстановява всяка проекция и кеш.

## Отхвърлено

общ `journal.jsonl` за всички задачи (merge конфликти между разработчици); `state.json` като източник (migrations); генериран survey в repo-то (гние, агентът му вярва); отделна memory подсистема (journal-ът + `git log -S` дават същото).

## Последствие

няма migrations framework; промяна на знание (`AGENTS.md`, skills, ADR, spec) е задача с behaviour 2 и човешки merge; паметта не се пренася между машини иначе освен през git.
